# FaqSection

FAQ accordion block for blog articles. Renders a list of
question/answer pairs as native `<details>/<summary>` accordion items
— no JavaScript required for the accordion itself to work.

There are two ways to use it, depending on who's authoring the
content.

---

## For editors: the marker syntax (Shopify blog editor)

Paste this into the article's HTML source view, wherever the FAQ
section should appear:

```html
<h2>Frequently Asked Questions</h2>

<script type="application/json" data-faq>
[
  {
    "question": "What's your return policy?",
    "answer": "You can return any unused item within 30 days of delivery for a full refund."
  },
  {
    "question": "How long does shipping take?",
    "answer": "Most orders arrive within 3–5 business days. Expedited shipping is available at checkout."
  }
]
</script>
```

The loader scans the article body for this exact marker
(`<script type="application/json" data-faq>...</script>`) and replaces
it with the real accordion markup before the page renders.

### Rules for the marker

- **Write your own `<h2>` heading above it.** The marker only
  replaces the accordion itself — it does not add a heading, so you
  won't get a duplicate "Frequently Asked Questions" heading if you've
  already written one.
- **The content inside the `<script>` tag must be valid JSON** — an
  array of objects. Plain HTML escaping rules don't apply here
  (apostrophes like "What's" are fine to type directly), but JSON
  syntax rules do: no trailing commas, and any literal `"` inside an
  answer needs to be escaped as `\"`.
- **If the JSON is invalid or the array is empty, the whole block is
  silently dropped** — the marker is left untouched in the page
  source (which renders as nothing, since browsers don't display
  `<script>` content), and no FAQ section appears. There's currently
  no in-admin warning when this happens, so if a FAQ section isn't
  showing up after publishing, the first thing to check is whether the
  JSON is valid (paste it into any JSON validator).
- **`type="application/json"` and the bare `data-faq` attribute must
  both be present exactly as shown** — the marker won't be recognized
  otherwise.

### Per-question fields

| Field | Required | Notes |
|---|---|---|
| `question` | Yes | Plain text |
| `answer` | Yes | Plain text |
| `id` | No | Custom HTML id for this question, e.g. for deep-linking (`#faq-shipping-time`). If omitted, one is generated from the question text. |
| `defaultOpen` | No | `true` to have this item expanded by default. |

Example with both optional fields:

```json
{
  "id": "faq-shipping-time",
  "question": "How long does shipping take?",
  "answer": "Most orders arrive within 3–5 business days.",
  "defaultOpen": true
}
```

**Tip on `id`:** if you don't set one, it's auto-generated by
slugifying the question text (e.g. "How long does shipping take?"
becomes something like `faq-how-long-does-shipping-take`). Two
questions with the same wording — even across separate FAQ sections in
the same article — can end up with the same id, which breaks deep
linking (only the first match will open when someone follows a link
to that id). Set an explicit `id` if you have duplicate or
near-duplicate questions.

## For developers: the `<FaqSection>` component

For a FAQ block hardcoded directly into a `.tsx` template rather than
authored by an editor:

```tsx
import {FaqSection} from '~/components/blogs/FaqSection';

<FaqSection
  items={[
    {
      question: "What's your return policy?",
      answer: 'You can return any unused item within 30 days of delivery for a full refund.',
    },
    {
      question: 'How long does shipping take?',
      answer: 'Most orders arrive within 3–5 business days.',
      defaultOpen: true,
    },
  ]}
/>
```

Differences from the marker path:

- **Renders its own `<h2>` heading** by default (`"Frequently Asked
  Questions"`), unlike the marker path. Pass `title={null}` to omit
  it, or `title="Custom heading"` to override it.
- **`answer` accepts `React.ReactNode`**, not just plain strings — you
  can pass JSX for a richer answer (links, formatting, etc.), which
  the marker path can't do since it's parsed from JSON.
- **`structuredData` prop** (defaults to `true`) controls whether the
  `FAQPage` JSON-LD block is emitted alongside the accordion — see the
  SEO note below before turning this off or on without thinking about
  it.

---

## Structured data (`FAQPage` JSON-LD) and SEO — read before assuming this helps rankings

Both the marker path and the component emit `FAQPage` JSON-LD
automatically, generated from the same question/answer data as the
visible accordion (so it can't drift out of sync — every answer in
the JSON-LD matches what's rendered on the page).

**Important, and easy to miss:** as of **May 7, 2026, Google fully
retired the FAQ rich result** — the expandable Q&A dropdown that used
to appear directly in search results. This applies to every site;
even the narrow government/health-site eligibility that had survived
since an August 2023 restriction is gone now. So adding `FAQPage`
markup will **not** get you that rich snippet anymore, regardless of
how correctly it's authored.

What's still true:

- `FAQPage` remains a valid Schema.org type. Google has said it's
  fine to leave existing markup in place — unused structured data
  doesn't cause problems for search rankings.
- Google has confirmed it still parses `FAQPage` markup to help
  understand page content, even without the visible rich-result
  feature.
- The *visible, plain-text* Q&A content (the actual rendered
  `<details>`/`<summary>` accordion) is unaffected by any of this —
  that's ordinary crawlable page content and was never dependent on
  the JSON-LD in the first place.

**Practical takeaway:** don't expect a search-results ranking or
snippet benefit from the `structuredData` flag anymore. It's
essentially free to leave on (no real cost, keeps things forward-
compatible in case other consumers — e.g. AI retrieval systems — make
use of it), but it is no longer the SEO lever it used to be. If you
ever consider hand-authoring a *separate* JSON-LD block instead of
relying on the automatic generation, don't — that reintroduces the
exact "answers can silently drift out of sync with the markup"
problem this automatic approach was built to avoid, for a feature that
no longer has a visible payoff to justify the risk.

---

## Non-string answers and structured data

If you're using the component (not the marker) with a JSX
`React.ReactNode` answer instead of a plain string, that item is
silently **excluded** from the `FAQPage` JSON-LD — only string answers
can be serialized into the `acceptedAnswer.text` field. The visible
accordion still renders it fine; only the structured-data block skips
it. Given the SEO note above, this is low-stakes today, but worth
knowing if you're relying on JSON-LD completeness for some other
purpose (e.g. feeding an internal tool).

---

## Shared markup / styling

Both entry points render the same `.accordion` / `.accordion__item` /
`.accordion__summary` / `.accordion__icon` / `.accordion__content`
class structure, styled in `app/assets/article.css`. No separate
stylesheet is needed for this block.

## No hydration step

Unlike the shoppable-embed, newsletter, video, and gallery blocks on
this route, FAQ content needs no client-side JavaScript to be
interactive — `<details>/<summary>` is natively expandable in every
browser. `injectFaqSections` renders straight to final static HTML on
the server; there's no slot, no portal, and no scan-on-mount step
required in the article route.
